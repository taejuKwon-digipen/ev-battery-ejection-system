# CoppeliaSim 배터리 투하 시뮬레이션 — 완전 초보자용 가이드

> 대상: 코딩은 되지만 **로봇 시뮬레이터는 처음 켜보는 사람**
> 목표: 가상 자동차에 배터리 블록을 매달고, 파이썬 명령 한 줄로 그 배터리를 떨어뜨리기
> 예상 소요: 처음 하면 2~3시간 (막히는 시간 포함)

---

## 읽기 전에 — 이 문서 사용법

- **위에서 아래로 순서대로** 하세요. 중간을 건너뛰면 반드시 뒤에서 막힙니다.
- 각 단계는 `무엇을 / 어떻게 / 화면에서 뭘 확인해야 하는지` 3개로 나뉘어 있습니다.
- 🔴 표시는 **여기서 대부분 막힘** 이라는 뜻입니다. 천천히 읽으세요.

---

## 용어 사전 (먼저 훑어보기, 외울 필요 없음)

| 용어 | 뜻 | 코딩으로 비유하면 |
| --- | --- | --- |
| **씬(Scene)** | 3D 작업 공간 전체. `.ttt` 파일로 저장됨 | 프로젝트 파일 |
| **오브젝트(Object)** | 씬 안의 모든 것 (바닥, 로봇, 블록, 카메라…) | 인스턴스 |
| **계층(Scene hierarchy)** | 오브젝트들의 부모-자식 트리 | DOM 트리 |
| **Shape** | 눈에 보이는 3D 덩어리 (큐브, 원기둥 등) | 실제 오브젝트 |
| **Joint(조인트)** | 두 물체를 이어주면서 **회전/직선 이동만 허용**하는 관절 | 제약 조건 |
| **Force sensor(포스센서)** | 두 물체를 **완전히 딱 붙여주는데, 끊을 수 있는** 연결부 | 끊어지는 용접 |
| **Static(정적)** | 중력·충돌을 무시하고 그 자리에 고정됨 | `position: fixed` |
| **Dynamic(동적)** | 물리 엔진이 계산함. 중력 받아서 떨어짐 | 물리 시뮬 대상 |
| **Respondable** | 다른 물체와 부딪힘. 꺼두면 유령처럼 통과함 | 충돌 판정 ON |
| **Handle(핸들)** | 오브젝트를 가리키는 정수 ID. 파이썬은 이걸로 조작 | 포인터 / 파일 디스크립터 |

## 🔴 시작 전에 반드시 이해할 것 2가지

이 두 개를 모르면 100% 막힙니다. 3분만 투자하세요.

### (1) 계층에서 자식으로 넣는다고 물리적으로 붙는 게 아닙니다

계층 트리에서 배터리를 자동차 밑으로 드래그하면 트리 구조상 자식이 됩니다.
**하지만 물리적으로는 붙지 않습니다.** 시뮬레이션을 켜면 배터리는 그냥 바닥으로 떨어집니다.

> HTML로 비유하면: `<div>` 안에 `<div>`를 넣은 건 맞는데, CSS로 위치를 안 잡아준 상태입니다.
> 트리 관계 ≠ 물리 결합.

두 개의 동적 물체를 **물리적으로 붙이려면** 그 사이에 **조인트나 포스센서가 반드시 있어야** 합니다.
그래서 구조가 이렇게 됩니다:

```
자동차  →  포스센서  →  배터리
        (이게 있어야 붙음)
```

### (2) 과제에 적힌 "조인트"를 그대로 쓰면 실패합니다

과제 체크리스트에는 "조인트로 연결하고, 조인트 해제 시 중력에 의해 떨어지도록"이라고 되어 있습니다.
그런데 실제로 조인트(prismatic = 직선 레일)를 쓰면:

- 모터를 꺼도 배터리는 **그 레일 축에 계속 묶여 있습니다.**
- 아래로 스르륵 미끄러지기만 하고, "툭 떨어지는" 연출이 안 나옵니다.

**포스센서**는 CoppeliaSim 공식 매뉴얼에도 *"두 shape 사이의 강체 링크이며, 조건이 되면 끊어질 수 있다"* 고 되어 있습니다.
평소엔 단단히 고정 → 비상시 끊어짐 → 자유낙하. 우리가 원하는 게 정확히 이겁니다.

> 📝 보고서/발표에는 그냥 **"락킹 링크(Locking Link) 해제 매커니즘"** 이라고 쓰면 됩니다.
> 오히려 "왜 조인트 대신 포스센서를 썼는가"를 설명하면 이해도 있어 보입니다.

# 0단계. 화면 익히기 (5분, 건너뛰지 마세요)

## 0-1. 실행

CoppeliaSim을 실행합니다. Edu 버전이면 시작할 때 라이선스 안내 창이 뜰 수 있는데, 확인 누르고 넘어가면 됩니다.

## 0-2. 화면 구성

처음 켜면 이렇게 생겼습니다:

```
┌─────────────────────────────────────────────────────┐
│ File  Edit  Add  Simulation  Tools  ...   ← 메뉴바   │
├─────────────────────────────────────────────────────┤
│ [🔍][↔][🔄]  [▶][⏸][⏹]  ...        ← 툴바(아이콘들) │
├──────────────┬──────────────────────────────────────┤
│ Scene        │                                      │
│ hierarchy    │                                      │
│ (계층 트리)   │         3D 화면                       │
│              │       (여기가 씬)                     │
├──────────────┤                                      │
│ Model        │                                      │
│ browser      │                                      │
│ (부품 창고)   │                                      │
└──────────────┴──────────────────────────────────────┘
```

- **왼쪽 위 = Scene hierarchy**: 씬에 뭐가 있는지 트리로 보여줌. 여기서 이름 바꾸고 부모 관계 바꿉니다.
- **왼쪽 아래 = Model browser**: 미리 만들어진 로봇/부품 창고. 여기서 드래그해서 가져다 씁니다.
- **가운데 = 3D 뷰**
- 패널이 안 보이면 툴바에서 해당 토글 아이콘을 찾아 켜세요. (아이콘에 마우스를 올리면 툴팁으로 이름이 뜹니다)

## 0-3. 🔴 마우스 조작 — 여기서 초보자가 제일 헷갈립니다

CoppeliaSim은 **"지금 마우스가 무슨 모드인지"** 에 따라 좌클릭 드래그 동작이 완전히 달라집니다.
툴바에 있는 이 버튼들이 모드 스위치입니다 (아이콘에 마우스 올려서 이름 확인):

| 모드 이름 | 좌클릭 드래그하면 |
| --- | --- |
| **Camera pan / shift** | 화면(카메라)이 좌우상하로 이동 |
| **Camera rotate** | 화면(카메라)이 빙글빙글 회전 |
| **Object/item shift** | **선택한 오브젝트가 움직임** |
| **Object/item rotate** | **선택한 오브젝트가 회전함** |

- 마우스 **휠**은 어느 모드에서든 줌인/줌아웃입니다.
- 💥 **"화면을 돌리려고 했는데 물체가 딸려 움직였다"** → Object 모드였던 겁니다. `Ctrl+Z`로 되돌리고 Camera 모드로 바꾸세요.
- 작업 중엔 평소 **Camera rotate** 모드로 두고, 물체 옮길 때만 Object 모드로 바꾸는 습관을 들이세요.

## 0-4. 오브젝트 선택 / 속성 열기

- **3D 화면에서 클릭** 또는 **계층 트리에서 클릭** → 선택됨 (테두리 강조)
- 계층에서 **아이콘을 더블클릭** → 속성 창(Scene Object Properties) 열림
- 계층에서 **이름 글자를 더블클릭** → 이름 편집 모드

> 이 둘 구분이 중요합니다. 아이콘 = 속성, 글자 = 이름 변경.

## 0-5. 시뮬레이션 실행/정지

툴바의 ▶(Play) / ⏸(Pause) / ⏹(Stop) 버튼입니다.

🔴 **가장 중요한 사실**: **⏹ Stop을 누르면 씬이 시작 전 상태로 자동 복구됩니다.**

- 배터리를 떨어뜨렸어도 Stop 누르면 원래 자리로 돌아옵니다.
- 즉 **아무리 망가뜨려도 Stop 한 번이면 리셋**입니다. 마음 놓고 실험하세요.
- 단, **시뮬레이션이 돌아가는 중(▶ 상태)에는 구조를 편집하지 마세요.** 반드시 ⏹ 먼저 누르고 편집합니다.

## 0-6. 단위 개념

- 길이는 전부 **미터(m)** 입니다. `0.1` = 10cm.
- 좌표는 **Z축이 위쪽**입니다. (`Z = 0`이 바닥)
- 무게는 **kg**.

# 1단계. 빈 씬 준비

**무엇을**: 깨끗한 작업 공간을 만듭니다.

**어떻게**:
1. 메뉴 `[File] → [New scene]`
2. 3D 화면에 회색 격자 바닥이 보이는지 확인

**확인**: 계층 트리에 `Floor` 비슷한 항목이 있어야 합니다. 없으면 Model browser의 `infrastructure` → `floors` 에서 하나 끌어다 놓으세요.

# 2단계. 자동차 가져다 놓기

**무엇을**: 미리 만들어진 로봇 모델(Pioneer 3-DX)을 씬에 배치합니다. 직접 만들 필요 없습니다.

**어떻게**:
1. 왼쪽 아래 **Model browser** 패널에서 폴더 트리를 찾습니다
2. `robots` → `mobile` 폴더 클릭
3. 아래쪽에 로봇 썸네일들이 쭉 뜹니다. 그중 **Pioneer 3-DX** 를 찾습니다 (회색/빨간 3바퀴 로봇)
4. 썸네일을 **3D 화면 위로 드래그 앤 드롭**

**확인**:
- 3D 화면에 로봇이 생김
- 계층 트리에 `PioneerP3DX` 항목 생김
- 트리 왼쪽 화살표(▶)를 눌러 펼치면 안에 `leftMotor`, `rightMotor` 등이 보임

> 💡 안 보이면 마우스 휠로 줌아웃 해보세요. 로봇이 화면 밖에 있을 수 있습니다.

## 2-1. 🔴 로봇에 딸려온 스크립트 제거하기

이 모델에는 **"혼자 알아서 돌아다니며 장애물을 피하는" Lua 스크립트**가 기본으로 붙어 있습니다.
우리는 파이썬으로 바퀴를 제어할 거라서, 이게 남아 있으면 **서로 명령이 충돌해서 차가 제멋대로 움직입니다.**

**어떻게**:
1. 계층 트리에서 `PioneerP3DX` 항목 오른쪽에 있는 **작은 스크립트 아이콘**(문서 모양)을 찾습니다
2. 그 아이콘을 **우클릭**
3. `[Remove] → [Associated child script]` 선택

**확인**: 스크립트 아이콘이 사라짐.

> 😌 실수로 잘못 지워도 괜찮습니다. Model browser에서 로봇을 다시 끌어오면 새 것이 옵니다.
> 삭제가 어려우면 메뉴 `[Tools] → [Scripts]` 창에서 해당 스크립트를 찾아 비활성화(disabled)해도 됩니다.

## 2-2. 시험 삼아 한번 돌려보기

▶ Play를 눌러보세요. 로봇이 **가만히 있으면 정상**입니다 (스크립트를 지웠으니까).
움직이면 스크립트가 아직 남아 있는 겁니다.
확인했으면 ⏹ Stop.

# 3단계. 배터리 블록 만들기

**무엇을**: 배터리 팩 역할을 할 직육면체를 만듭니다.

**어떻게**:
1. 메뉴 `[Add] → [Primitive shape] → [Cuboid]`
2. 크기 입력 창이 뜹니다. 이렇게 넣으세요:
   - X size = `0.12`
   - Y size = `0.10`
   - Z size = `0.05`
   (12cm × 10cm × 5cm — 로봇 크기에 적당한 배터리 팩 비율)
3. OK

**확인**: 화면 어딘가(보통 원점)에 회색 상자가 생기고, 계층에 `Cuboid` 가 추가됨.

## 3-1. 이름 바꾸기 (🔴 오타 주의)

파이썬 코드가 **이 이름으로** 물체를 찾습니다. 정확해야 합니다.

**어떻게**:
1. 계층 트리에서 `Cuboid` **글자 부분을 더블클릭**
2. `EV_Battery` 로 변경 후 Enter

**확인**: 계층에 `EV_Battery` 로 표시됨. 대소문자, 언더바 위치까지 정확한지 다시 보세요.

## 3-2. 위치 잡기

**무엇을**: 배터리를 자동차 **뒤쪽에 매달린** 위치로 옮깁니다.

> ❓ 왜 하부가 아니라 후방인가?
> Pioneer는 차체 바닥과 지면 사이 간격이 몇 cm밖에 안 됩니다. 하부에 배터리를 넣으면 떨어져봤자 바로 바닥에 닿아서 **낙하 연출이 안 보입니다.**
> 후방에 매달면 낙하 경로가 뻥 뚫려 있어서 "툭 떨어지고 차가 도망간다"는 그림이 제대로 나옵니다.
> 제안서에도 *"차체 하부 **또는 후면**"* 이라고 되어 있으니 조건 위반도 아닙니다.

**어떻게**:
1. 계층에서 `EV_Battery` 를 **선택**
2. 툴바에서 **[Object/item shift]** 아이콘 클릭 (아이콘에 마우스 올려서 이름 확인 — 십자 화살표 모양)
3. 뜬 창에서 **`Position`** 탭 선택
4. `Relative to:` 드롭다운을 **`PioneerP3DX`** 로 변경
   → 이제 입력하는 좌표가 "자동차 기준 상대 위치"가 됩니다
5. 입력:
   - X = `-0.25`  (자동차 뒤쪽)
   - Y = `0`
   - Z = `0`
6. Apply / 적용

**확인 (눈으로 봐야 합니다)**:
- ✅ 배터리가 자동차 **뒤쪽 공중에** 떠 있음
- ✅ 자동차 몸통과 **겹치지 않음**
- ✅ 바닥에 **닿지 않음**

> 🔧 만약 배터리가 자동차 **앞쪽**에 생겼다면, 이 모델의 앞 방향이 반대인 겁니다. X를 `+0.25`로 바꾸세요.
> 겹치거나 바닥에 닿으면 X, Z 값을 조금씩 조정하면서 화면을 보세요. **정확한 숫자보다 눈으로 보이는 게 맞는 게 중요합니다.**

# 4단계. 🔴 배터리에 물리 속성 주기 (이거 빠뜨리면 절대 안 떨어짐)

**무엇을**: 방금 만든 상자는 지금 "장식품"입니다. 중력도 안 받고 충돌도 안 합니다.
이걸 진짜 물리 객체로 바꿔줍니다.

**어떻게**:
1. 계층에서 `EV_Battery` 의 **아이콘을 더블클릭** → `Scene Object Properties` 창이 열림
2. 창 위쪽 탭 중 **`Shape`** 탭 선택
3. **`Show dynamic properties dialog`** 버튼 클릭 → 새 창이 열림
4. 이 창에서 3개를 설정합니다:

| 항목 | 설정 | 안 하면 생기는 일 |
| --- | --- | --- |
| `Body is respondable` | ☑ **체크** | 배터리가 바닥을 뚫고 지구 중심으로 사라짐 |
| `Body is static` | ☐ **체크 해제** | 중력을 안 받아서 공중에 영원히 떠 있음 |
| `Mass` | `0.3` 입력 | 너무 가벼우면 물리 계산이 튀면서 이상하게 날아감 |

5. Mass를 입력한 뒤 같은 창의 **`Compute mass & inertia properties`** 버튼을 눌러주세요.
   (관성 모멘트를 자동 계산해줍니다. 안 하면 회전이 부자연스러워집니다)

**확인**: ▶ Play를 눌러보세요.
→ **배터리가 바닥으로 떨어지면 정상입니다.** 아직 자동차에 안 붙였으니 당연합니다.
→ 안 떨어지면 `Body is static` 체크가 안 풀린 겁니다.
⏹ Stop 누르면 원위치로 돌아옵니다.

# 5단계. 🔴 배터리를 자동차에 붙이기 (락킹 매커니즘)

여기가 이 프로젝트의 핵심입니다.

## 5-1. 포스센서 추가

**어떻게**:
1. 메뉴 `[Add] → [Force sensor]`

**확인**: 계층에 `EV_Battery_Link` 가 생김. (3D 화면에서는 작은 표식으로 보입니다)

## 5-2. 포스센서 위치 잡기

배터리와 자동차를 잇는 "연결부"이므로, 배터리 바로 근처에 둡니다.

**어떻게**:

## 5-3. 부모-자식 관계 연결

**어떻게** (계층 트리에서 드래그 앤 드롭):
1. `EV_Battery` 를 끌어서 `EV_Battery_Link` **위에 놓기**
2. `EV_Battery_Link` 를 끌어서 `PioneerP3DX` **위에 놓기**

**확인**: 계층 트리가 정확히 이 모양이어야 합니다:

```
Floor
PioneerP3DX
 ├─ leftMotor
 ├─ rightMotor
 ├─ (기타 부품들…)
 └─ EV_Battery_Link      ← 포스센서
      └─ EV_Battery      ← 배터리 블록
```

🔴 **`EV_Battery` 가 `EV_Battery_Link` 의 자식이고, `EV_Battery_Link` 가 `PioneerP3DX` 의 자식**이어야 합니다.
`EV_Battery` 가 `PioneerP3DX` 바로 밑에 있으면 안 됩니다. 그러면 물리적으로 안 붙습니다.

> 드래그가 잘 안 되면 항목을 정확히 대상 **글자 위에** 떨어뜨려 보세요. 살짝 어긋나면 형제로 들어갑니다.

# 10단계. 최종 테스트 — 배터리 투하

**어떻게**:

```bash
python battery_drop_test.py
```

**화면에서 볼 것**:
1. 시뮬레이션이 **자동으로 시작**됨 (▶ 를 파이썬이 눌러줌)
2. 자동차가 3초간 앞으로 전진
3. 1초간 감속 (WARNING 상태 흉내)
4. 정차 후 멈춘 채로 대기 (ARMED - 아직 배터리는 안 떨어짐)
5. 터미널에서 Enter를 누르면 → **배터리가 툭 떨어짐** 💥

**터미널에서 볼 것**:
```
[1] 초기 배터리 높이 : 0.1500 m
[2] 정상 주행 3초...
[4] 위험 감지 - 정차 후 분리 대기(ARMED)
    배터리를 분리하려면 수동으로 래치를 당겨야 합니다.
    래치를 당기려면 Enter를 누르세요...
[5] 분리 확정
    t+0.5s  z = 0.0850 m
    t+1.0s  z = 0.0250 m
[6] 최종 배터리 높이 : 0.0250 m  (하강 0.1250 m)
    ✅ 낙하 성공 - 링크 해제 매커니즘 정상 동작
[7] 분리 완료 - 도망가지 않고 그 자리에 정차 유지
```

"래치를 당기려면 Enter를 누르세요..."에서 멈춰 있는 게 정상입니다 — "정차했다고 바로 떨어뜨리면 다른 차가 밟을 수 있다"는 문제 때문에 자동 즉시분리를 없애고, 사람이 수동으로 래치를 당겨야(Enter) 실제로 분리되도록 바꾼 것입니다(`ejection_sim.py`의 `arm()` / `confirm_eject()`).

**이게 나오면 3번 파트 체크리스트 5개 전부 완료입니다.** 🎉

# 11단계. 팀 통합 (4번 공통 파트)

## 11-1. 다른 팀원에게 넘길 것

2번(데이터) 담당자에게 `ejection_sim.py` 파일과 **아래 코드**를 알려주면 됩니다:

```python
from ejection_sim import EjectionSim

sim = EjectionSim()
sim.connect()
sim.start()

# --- 시리얼 읽고 필터 돌리는 메인 루프 안에서 ---
sim.drive(1.5, 1.5)      # 정상 주행

if danger_flag:
    sim.arm()                    # 정차만 함 - 아직 분리 안 됨
    if area_clear_flag:          # 후방 클리어 확인(초음파 등) 또는 사람의 확인
        sim.confirm_eject()      # 여기서 실제로 분리됨
```

`danger_flag`만 보고 바로 `eject()`를 부르면 안 됩니다 — "정차했다고 바로 떨어뜨리면 다른 차가 밟을 수 있다"는 문제 때문에, `arm()`(정차+준비)과 `confirm_eject()`(실제 분리)를 분리해뒀습니다. `arm()` 없이 `confirm_eject()`를 부르면 무시되고, 이미 분리된 상태에서 다시 불러도 안전하게 아무 일도 안 일어납니다 — 루프 안에서 매번 호출해도 괜찮습니다.

사람이 지켜보는 데모라면 `area_clear_flag` 대신 그냥 키보드 입력(`input()`)으로 확인해도 됩니다 (`battery_drop_test.py` 참고).

## 11-2. 구조 권장안

시리얼 읽기 + 필터 + matplotlib + CoppeliaSim 제어를 **하나의 파이썬 스크립트**에서 다 돌리세요.
프로세스를 나누면 프로세스 간 통신을 또 만들어야 해서 과제 규모에 비해 과합니다.

단, matplotlib이 화면을 그리느라 루프를 멈추기 쉬우니, 데이터 담당자에게 **`plt.pause(0.01)`** 이나 **`FuncAnimation`** 을 쓰라고 미리 말해두세요. 안 그러면 "센서는 뜨거운데 배터리가 안 떨어진다"는 상황이 생깁니다.

## 11-3. 아두이노 FSM ↔ 시뮬레이션 대응표

발표 자료에 넣기 좋은 표입니다.

| 아두이노 FSM 상태 | 시뮬레이션 함수 | 화면에서 보이는 것 |
| --- | --- | --- |
| `NORMAL` | `sim.forward(1.5)` | 정상 주행 |
| `WARNING` | `sim.slow()` | 감속 |
| `STOPPED` | `sim.halt()` | 정차 |
| `EJECTED` | `sim.eject()` | 배터리 낙하 |
| 리셋 버튼 | `sim.reset()` | 배터리 재장착, 처음 상태로 |

# 부록 A. 오류 사전

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 파이썬: `ConnectionError` / 무한 대기 | CoppeliaSim이 꺼져 있음 | 시뮬레이터 먼저 실행 |
| `No such function: zmqRemoteApi.require` | 라이브러리 버전이 시뮬레이터 버전과 안 맞음 | `pip install -U coppeliasim-zmqremoteapi-client` |
| `ModuleNotFoundError: coppeliasim_zmqremoteapi_client` | 설치 안 됨 / 다른 파이썬 환경에 설치됨 | 가상환경 확인 후 재설치 |
| 오브젝트를 못 찾음 | 이름 오타 | `check_scene.py` 실행 |
| 배터리가 시작부터 떨어짐 | 포스센서가 중간에 없음 | 5-3 계층 구조 확인 |
| 분리 명령을 줘도 안 떨어짐 | `Body is static` 켜져 있음 / 차체에 끼임 | 4단계 재확인, 위치 조정 |
| 배터리가 바닥을 통과함 | `respondable` 미체크 | 4단계 재확인 |
| 차가 안 움직임 | Lua 스크립트가 남아 있음 / 모터 경로 오타 | 2-1 재확인 |
| 물체가 부들부들 떨림 | 질량이 너무 작음 / 물체가 서로 겹침 | Mass ↑, 위치 조정 |
| 실수로 물체를 옮겨버림 | Object shift 모드였음 | `Ctrl+Z`, Camera 모드로 전환 |
| 뭘 해도 이상함 | — | ⏹ Stop 누르고, 저장 안 한 채 씬 다시 열기 |
